# 智小匠学生成长与班级治理平台比赛版 MVP 技术设计

版本：V1.0  
状态：MVP 实施版（前后端骨架与班主任端页面已落地）  
项目代号：`zhixiaojiang`

## 1. 文档目的

本文档用于指导“智小匠”比赛版 MVP 的产品设计与后续开发。首期以班主任为核心用户，通过班级驾驶舱、学生画像、智能预警、一人一策和班级诊改等功能，形成可完整演示的数字育人闭环。

本文件是设计和实施依据。当前代码已落地前后端工程、幂等数据库初始化、Oracle 公网直连配置、登录与主要业务查询接口；生产数据库账号、网络策略和 AI 密钥仍由部署环境注入。SSH 隧道脚本作为关闭公网端口时的备用方案保留。

## 2. 建设范围

### 2.1 首期目标

比赛版 MVP 重点完成以下九个页面：

1. 登录页；
2. 班级数字驾驶舱；
3. 学生列表；
4. 学生数字画像；
5. 机智币；
6. 智能预警；
7. 一人一策；
8. 六机成长任务；
9. 班级诊改中心。

首期必须支持以下连续演示流程：

```text
班级驾驶舱发现异常
        ↓
查看学生数字画像与成长趋势
        ↓
规则引擎生成智能预警
        ↓
AI 提供辅助分析与帮扶建议
        ↓
班主任审核并建立一人一策
        ↓
记录帮扶执行过程
        ↓
复评学生成长变化
        ↓
更新班级诊改指标
```

### 2.2 首期边界

首期实际开放班主任端。学生端、家长端和系统管理端仅保留架构扩展位置，不进入比赛版开发范围。

以下能力不纳入首期：

- 学校统一身份认证；
- 短信、微信和企业微信通知；
- 家长端敏感信息授权；
- MinIO 或 OSS 文件上传；
- 真实心理测评与自动心理诊断；
- 自动奖惩、处分或评优决策；
- 多学校、多年级和多租户管理。

## 3. 业务设计原则

平台围绕“一脑、一档、四维、六机、八环”展开：

| 架构 | 系统表达 |
|---|---|
| 一脑 | 智小匠 AI 育人大脑 |
| 一档 | 一生一档学生成长电子档案 |
| 四维 | 品德、技能、思维、智行 |
| 六机 | 铸机魂、立机规、淬机质、铺机路、聚机力、调机态 |
| 八环 | 目标、标准、计划、实施、监测、诊断、改进、优化 |

AI 仅承担数据归纳、趋势解释和建议生成。涉及心理、安全、处分、评奖评优及高风险事件时，必须由教师人工研判和确认。

## 4. 总体技术架构

### 4.1 技术选型

| 层级 | 技术方案 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、Lucide 图标（当前 MVP）；路由以路径与视图状态保持轻量实现 |
| UI 与图表 | 自定义 CSS 主题与可访问原生控件（当前 MVP）；Element Plus/ECharts 作为后续组件化扩展位 |
| 后端 | Java 17、Spring Boot 3、Spring Security、JWT、JdbcTemplate |
| 数据 | MySQL 8、Redis |
| AI | 规则引擎加 OpenAI 兼容 API |
| 部署 | 本机 Vite + Spring Boot；Docker/Nginx 作为后续部署扩展 |

项目命名统一如下：

| 对象 | 名称 |
|---|---|
| Git 主项目 | `zhixiaojiang` |
| Maven 父工程 | `com.zhixiaojiang:zhixiaojiang`（`packaging=pom`，仓库根目录 `pom.xml`） |
| Maven 子模块 | `zhixiaojiang-server`（当前唯一参与 Maven 生命周期的模块） |
| 前端工程 | `zhixiaojiang-web`（独立 npm 工程，不登记为 Maven module） |
| 后端工程 | `zhixiaojiang-server` |

| Java 根包 | `com.zhixiaojiang` |

后端使用 Maven 父子工程管理：根目录 `pom.xml` 为聚合父 POM，统一约束 Java 版本、依赖版本与插件版本，子模块只声明 artifactId 与依赖；前端保持独立 npm 工程，由 npm 单独构建与部署，因此 Maven 构建不依赖 Node 环境。后端命令在仓库根目录执行：`mvn test`、`mvn -DskipTests package`、`mvn -pl zhixiaojiang-server spring-boot:run`。

## 5. 前端视觉规范

### 5.1 设计基准

前端视觉以用户提供的控制台截图为首要基准，以 [bytecat 控制台](https://www.bytecatcode.org/dashboard) 和 [首页](https://www.bytecatcode.org/) 为补充观察来源。目标是忠实复原截图中的布局比例、视觉密度和组件形态，再适配智小匠业务内容。品牌名称、Logo、业务文案和学生数据使用智小匠自身内容。

观察日期：2026-09-14。本轮已查看网站首页和控制台首屏，并读取可见元素的计算样式；未逐一检查原站其他页面、弹窗和全部交互状态，因此不能把本稿表述为“全站已经完成 1:1 复原”。后续实施先验证控制台视觉基线，再将同一套组件规则用于其他业务页面。

实测与设计约定分开记录：

| 项目 | 来源与结论 |
|---|---|
| 顶栏、侧栏 | 在 1470×797 CSS 像素视口中实测为 48px、208px |
| 主画布位置 | 同一视口中实测左侧 x=208px、顶部 y=56px，右侧和底部留出 8px |
| 字体 | 可见元素计算样式包含 Lora、Source Serif、Noto Serif SC、Songti SC 等衬线字体；声明字体栈不代表所有字体均已加载 |
| 正文与控件 | 已观察正文 16px/24px、按钮 14px/20px |
| 边框与阴影 | 已观察 1px 边框和 `0 1px 2px rgba(0,0,0,0.05)` 卡片阴影 |
| 卡片圆角 | 部分可见卡片实测为 8.64px，嵌套区域为 6.72px；下文的整像素规格属于适配初稿，忠实复原时须通过截图对照校准 |
| 配色 | 当前可见控件呈暖白、珊瑚橙主题，但根节点默认令牌呈白蓝色，与元素实际计算样式不同；不得直接复制根节点默认令牌作为截图主题 |
| 悬停、弹窗、移动布局 | 下文为智小匠设计约定，尚未证实与原站完全一致 |

用户截图含外围黑色边框及缩放，黑边不属于页面样式。像素对比必须先统一内容视口、浏览器缩放和字体加载状态。

“智小匠”沿用参考站的以下视觉特征：

- 暖白背景与低饱和中性色；
- 纤细灰色边框与极轻阴影；
- 48px 吸顶顶栏和 208px 固定侧栏；
- 主内容区域采用内嵌式圆角画布；
- 中文衬线字体带来沉稳、教育性和人文感；
- 珊瑚橙作为主操作色；
- 卡片高密度排列，不使用大面积渐变、玻璃拟态或厚重阴影；
- 信息层级依靠留白、字重、细分隔线和淡色背景建立。

### 5.2 品牌适配原则

参考站中的像素猫元素替换为“智小匠”像素机器人头像。机器人图形只作为品牌识别和空状态点缀，不大面积装饰页面。

系统名称统一显示为“智小匠”，辅助标识可使用“机智班”。不得在成品中出现 bytecat、API 网关、钱包、模型市场等原站品牌或业务内容。

### 5.4 字体与字号

字体栈采用与参考站一致的中文衬线方向：

```css
font-family:
  "Lora Variable",
  Lora,
  "Source Serif 4",
  "Noto Serif SC",
  "Source Han Serif SC",
  "Songti SC",
  STSong,

```

数字指标和代码类信息使用：

```css
font-family:
  ui-monospace,
  SFMono-Regular,
  Menlo,
  Monaco,
  Consolas,
  monospace;
```

| 层级 | 字号与行高 | 字重 |
|---|---|---|
| 页面标题 | 24px / 32px | 600 |
| 区块标题 | 18px / 28px | 600 |
| 卡片标题 | 16px / 24px | 600 |
| 正文 | 16px / 24px | 400 |
| 控件与菜单 | 14px / 20px | 400 或 500 |
| 辅助信息 | 12px / 16px | 400 |
| 核心数字 | 28px / 34px | 700，等宽字体 |

不得通过缩小到 12px 以下来塞入更多信息。中文正文保持自然字距，不使用大范围粗体。

### 5.5 页面骨架

桌面端以 1440px 至 1920px 为主要比赛展示宽度：

```text
┌──────────────────────────── 48px 顶栏 ────────────────────────────┐
│ 品牌              一级导航                搜索 / 通知 / 用户      │
├──────── 208px 侧栏 ────────┬─────────────────────────────────────┤
│ 分组菜单                   │ 8px 外边距                           │
│                            │ ┌──────── 圆角主画布 ─────────────┐ │
│                            │ │ 页面标题与操作                    │ │
│                            │ │                                  │ │
│                            │ │ 高密度响应式卡片网格              │ │
│                            │ └──────────────────────────────────┘ │
└────────────────────────────┴─────────────────────────────────────┘
```

关键尺寸：

| 区域 | 规范 |
|---|---|
| 顶栏 | 高 48px，吸顶，70% 至 85% 不透明暖白背景，轻微模糊，底部 1px 边框 |
| 侧栏 | 宽 208px，桌面固定，背景比主画布略深 |
| 主画布 | 外边距 8px，圆角 12px，白色背景，极轻阴影 |
| 页面内边距 | 桌面 16px 至 20px，移动端 12px |
| 内容间距 | 12px 或 16px，不使用随意数值 |
| 卡片圆角 | 一级 12px，二级 8px，按钮 6px 至 8px |
| 卡片边框 | 1px `--border` |
| 卡片阴影 | `0 1px 2px rgba(0, 0, 0, 0.05)` |

### 5.6 顶栏

左侧放置折叠按钮、像素机器人 Logo 和“智小匠”文字标识。中间一级导航建议为：

- 首页；
- 班级驾驶舱；
- 学生成长；
- 六机任务；
- 诊改中心；
- 帮助。

右侧保留全局搜索、通知和教师头像。比赛版不放语言切换、主题切换和无实际功能的入口。

搜索框宽度在桌面端为 256px，默认提示“搜索学生、任务或预警”，支持 `Ctrl/Command + K` 聚焦。通知图标只有存在未处理事项时才显示数字角标。

### 5.7 侧栏

菜单按照任务场景分组：

```text
工作台
  概览

学生成长
  学生档案
  成长画像
  机智币

育人闭环
  智能预警
  一人一策
  六机任务

诊断评价
  班级诊改
```

侧栏菜单项高 40px，左右内边距 12px，图标 18px。激活项使用 `--card-soft` 背景、深色文字和 600 字重，不使用高饱和色块或左侧粗色条。

### 5.8 卡片和控件

- 一级卡片使用淡暖灰底、1px 边框、12px 圆角和极轻阴影。
- 嵌套卡片使用白色或半透明白色，8px 圆角。
- 主按钮使用珊瑚橙实底和白色文字；次按钮使用白底灰边框。
- 表单控件高 36px，重要操作按钮高 38px 至 40px。
- 图标统一使用 Lucide 线性图标，线宽保持一致，不混用表情符号。
- 状态标签使用浅色底加深色文字，不能只依靠颜色表达状态。
- 表格行高不低于 48px，表头使用淡灰背景；悬停只做轻微背景变化。
- 图表弱化坐标轴和网格线，数据颜色限定为主色、绿色、蓝色和黄色四组。

### 5.9 动效

动效只用于反馈层级变化：

- 悬停和焦点过渡：150ms；
- 侧栏展开与抽屉：200ms；
- 卡片进入：不超过 240ms；
- 禁止大面积浮动、弹跳、粒子和持续闪烁；
- 用户开启减少动态效果时，关闭非必要动画。

## 6. 九个页面的视觉映射

### 6.1 登录页

登录页沿用参考站首页的左右双栏构图：左侧为品牌、建班理念和登录表单，右侧为“采—诊—策—评”闭环演示卡片。背景使用极淡的蓝绿柔光，不放宣传型大图。

### 6.2 班级数字驾驶舱

驾驶舱严格复用参考控制台的首屏结构：

```text
┌────────────────────────────────────┬──────────────┐
│ 班级运行态势与育人闭环             │ 今日建议操作 │
│ ┌──────────────┬─────────────────┐ │              │
│ │ 四步闭环清单 │ 重点学生提示卡  │ │ 待处理预警   │
│ └──────────────┴─────────────────┘ │ 待审核方案   │
├─────────────────────────────┬──────┴──────────────┤
│ 核心指标卡：人数/出勤/指数/任务率 │ 四维雷达与状态 │
└─────────────────────────────┴─────────────────────┘
```

参考站的“开始使用”面板替换为“班级运行态势”，三步引导替换为“采集—诊断—施策—复评”，代码请求卡替换为重点学生趋势摘要，推荐操作替换为教师待办。

### 6.3 学生列表

页面顶部为标题、班级筛选、状态筛选和搜索；主体为紧凑表格。学生姓名、成长指数、四维短板、预警等级、最新变化和操作入口必须在一屏内可浏览。

### 6.4 学生数字画像

首屏采用左侧档案摘要、中间四维雷达图、右侧成长建议的三栏结构；下方展示趋势图和成长时间轴。AI 建议区域必须固定显示“AI 辅助建议，仅供教师参考”。

### 6.5 机智币

顶部展示积分总览和四类积分分布，下方为积分流水与规则。加减分使用颜色、正负号和文字三重表达，不能只显示红绿颜色。

### 6.6 智能预警

首屏突出待处理预警列表和当前选中学生的趋势证据。预警等级固定为正常、关注、重点关注和人工研判，不使用“问题学生”等标签。

### 6.7 一人一策

采用左侧方案列表、中间帮扶计划、右侧教师审核与过程状态布局。AI 生成内容默认处于草稿状态，必须经过教师确认后才能进入执行中。

### 6.8 六机成长任务

顶部用六个紧凑标签切换铸机魂、立机规、淬机质、铺机路、聚机力和调机态。主体使用任务卡片与完成进度，不做大面积彩色看板。

### 6.9 班级诊改中心

围绕八字循环展示目标值、当前值、偏差、原因、改进措施和复评结果。流程状态使用横向步骤条，下方以趋势图和诊改记录支撑结论。

## 7. 响应式规范

| 断点 | 行为 |
|---|---|
| `≥ 1280px` | 完整顶栏、208px 侧栏和多列卡片布局 |
| `768px–1279px` | 侧栏可折叠为图标栏，顶部搜索缩短，卡片改为两列 |
| `< 768px` | 侧栏变为抽屉，顶部只保留品牌与必要操作，卡片单列，表格允许横向滚动 |

比赛验收以 1440×900 和 1920×1080 为主，同时保证 390×844 移动视口不存在页面级横向溢出。

## 8. 无障碍与内容规范

- 正文与背景对比度至少达到 WCAG AA；
- 所有图标按钮必须提供可读名称；
- 键盘焦点使用清晰的蓝色焦点环；
- 图表必须附带文字摘要或可读取的数据表；
- 预警不能只依赖颜色区分；
- 页面不公开心理敏感信息、内部风险标签和其他学生数据；
- 空状态说明下一步行动，不使用没有意义的装饰；
- 错误信息使用具体、可恢复的表达。

## 9. 核心数据模型

首期数据表包括：

## 10. API 设计约定

统一前缀为 `/api/v1`，使用 JSON 传输和 JWT 鉴权。响应结构：

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "requestId": "01J..."
}
```

分页结构：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 42

```

核心接口：


## 11. AI 能力设计

后端设置统一的 AI Provider 接口，使用配置切换不同 OpenAI 兼容服务。规则判断和大模型职责严格分离：

- 连续成绩下降、迟到增加、任务未完成等事实由规则引擎计算；
- 趋势归纳和教育建议由大模型生成；
- 教师确认后才能生成正式帮扶方案；
- AI 调用前移除姓名、电话、住址和家长信息；
- AI 不生成医学或心理诊断结论。

AI 返回结果必须是结构化对象：

```json
{
  "summary": "近期学业、活动参与和行为表现同步下降",
  "evidence": ["数学成绩连续三次下降", "近两周迟到三次"],
  "attentionAreas": ["学习困难", "时间管理", "目标动力"],
  "suggestions": ["班主任个别谈话", "安排数学教师辅导"],
  "disclaimer": "AI辅助建议，仅供教师参考",
  "requiresTeacherConfirmation": true
}
```

AI 服务不可用时，系统使用规则说明和预置教育建议模板降级，保证比赛演示不中断。

## 14. 验收标准

### 14.1 文档验收

- 九个页面均能映射到业务模块、核心数据和 API；
- 视觉令牌、布局尺寸和组件规则无相互矛盾；
- 不包含参考站品牌和业务内容；
- 不存在未解释的 `XX` 或关键占位符；
- AI 的事实判断、建议生成和教师确认边界清晰。

### 14.2 后续前端视觉验收

待正式实施后，以用户提供的控制台截图作为视觉回归基准。先制作布局与组件复原验证页，通过对照后再替换业务内容；该验证页属于后续实施内容，本轮未创建。重点比较：

- 顶栏与侧栏尺寸比例；
- 主画布边距和圆角；
- 卡片背景、边框、阴影和间距；
- 字体层级与中文排版；
- 主色按钮和状态色使用；
- 首屏信息密度；
- 1440×900、1920×1080 和 390×844 三个视口。

允许替换品牌、业务内容和图表类型；不允许退化为常见蓝色后台模板，也不允许擅自加入高饱和渐变、大阴影或营销型大屏视觉。

布局与视觉验收分两步：先在与参考一致的内容视口中对照顶栏、侧栏、卡片边界和字体，不以其他分辨率的截图冒充像素一致；再验证智小匠各页面与响应式布局。字体渲染差异单独记录，视觉风格不能通过更换 Vue 技术栈或直接使用 Element Plus 默认主题来替代。

### 14.3 技术初稿待深化项

本稿已确定范围、技术栈和视觉方向，当前 MVP 已补齐主要表结构（含出勤、行为、技能、四维评价、积分规则、AI 分析与诊改记录）、统一响应、规则预警、积分幂等/撤销、帮扶状态转换和冒烟脚本。AI 真实服务仍通过配置接入；未配置时使用明确标记为 `TEMPLATE` 的建议。示例指标不能当作真实班级成效，模拟复评数据不能自动修改正式业务记录。

## 15. 实施门禁

本版本已进入实施阶段。仓库采用 Maven 父子工程管理后端：仓库根目录为聚合父 POM（`packaging=pom`），当前登记 `zhixiaojiang-server` 一个后端子模块，统一约束 Java 版本、依赖版本与插件版本；前端 `zhixiaojiang-web` 为独立 npm 工程，不参与 Maven 生命周期。数据库脚本、公网直连配置和接口冒烟测试均已就绪；Docker、公网发布和学生/家长端仍不在本轮范围内。

日期：2026-09-16。依据：本轮提供的 7 张参考截图，以及当前 `zhixiaojiang-web/src` 源码。

## 实施进度（2026-09-17）

用户确认后已进行第一轮组件统一，保留原有配色与业务接口。下方第 1–后续章节保留为实施前核对基线，其中“尚未创建”“未抽组件”等描述不代表此刻状态。

- 新增共用组件：`PageHeader`、`EmptyState`、`PaginationBar`、`SegmentedControl`、`MetricStrip`，位于 `zhixiaojiang-web/src/components/ui/`。

验证：`npm run build`（包含 TypeScript 检查）通过。已查看登录后概览与学生页加载阶段；后续浏览器登录请求持续等待，因此尚未完成登录后的分页操作、空状态及手机布局验收。此处不宣称逐像素复原或完整交互验收通过。

边界：本轮没有新增支付、API 密钥、账号绑定、安全设置等业务，也没有实现全部建议组件；图表卡、资料头、时间状态带等仍以原页面实现为准。后续扩展应以真实数据和业务需求为依据。

## 1. 结论与范围

现有项目已经具备业务页面、基础表单、表格、状态标签、分页、弹窗和图表，但主要是“页面组件 + 公共 CSS + 各页局部样式”，尚未形成一致的基础组件层。

本轮只提取参考中的组件结构并核对现状，不修改页面、接口、数据库或依赖。下面的组件名称是建议命名，不代表已经创建了这些文件。

- 用户已确认截图颜色来自换肤：颜色不纳入本轮差异判断，也不作为整改项。保留项目现有配色。
- 重点提取布局、控件组合、尺寸、间距、排版、状态表达和信息层级；文字的字形与字号仍单独核对，不把色差当作结构差异。
- 不恢复此前删除的顶部六项导航、参考切换入口或“视觉复原”标签标题。
- 本次是截图与源码核对，不是当前页面的浏览器逐像素验收。截图无法证明下拉、悬停、弹窗、移动端、保存及错误处理的具体行为，也无法确定原站使用的组件库。
- 截图经过缩放和裁切；下文建议尺寸不是原站 CSS 的精确测量值。不提取截图中的真实用户邮箱、账号 ID 等个人资料作为演示数据。

## 4. 当前尺寸、排版与建议规范

### 4.1 已确认的源码参数

| 项目 | 当前值 / 实现 |

| 卡片圆角 | 公共面板 9px，部分子卡 6/7/10px |
| 表格 | 表头和数据行公共高度 54px；表头 13px、表格 14px |
| 页面标题 | 概览 20px，业务页 27px；存在层级差异 |

这些是当前源码值，不是从截图反推的原站精确值。

### 4.2 建议统一规则（待实施，不调整配色）

- 间距采用 4/8/12/16/20/24px 档位；页面级卡片间距优先 16px。
- 控件设紧凑 28px、默认 36px 两档；手机主要触控目标可增至至少 44px，不用缩小文字硬塞。
- 表单圆角以 6px 为主，卡片以 8–10px 为主，保持细边框、轻阴影。
- 表格、表单和设置页按“标题区—内容区—操作区”建立清晰层级，通过边界、间距和对齐来统一，不以换色解决结构问题。
- 页标题、卡片标题、字段标签、正文、提示、数字分别定义层级，不让每个页面单独决定大小。
- 表格空状态在内容区居中，采用图标+短标题+解释；有真实创建能力时才出现行动按钮。不要复制截图中的超大空白和拼接偏移。
- 较宽表格保留横向滚动，过滤区允许换行；设置双栏在小屏堆叠，分页允许换行。
- 状态带的灰色表示未登记/无样本；成绩缺失和无到期任务不填 0，不能因为参考图显示 0 就改掉指标口径。
- 学生预警保留“关注”“重点关注”“人工研判”等教育语义，不使用模型状态页中的“中断”来标记学生。

## 6. 实际依赖与组件化顺序

当前 `package.json` 有 Vue 3、TypeScript、Vite、Lucide 和字体依赖。没有声明 Element Plus、ECharts、Vue Router、Pinia、Axios。图表是手写 SVG，请求封装在 `src/api.ts`；不能把早期计划里的组件库算作当前已经使用的技术。

建议按以下顺序逐步实施，不为对照截图一次性引入整套组件库：

1. **清理事实性文案和占位入口**：数据来源、离线提示、语言入口。
2. **统一公共样式**：按钮、字段、卡片、状态标签、焦点、间距；保留既有主题。
3. **抽共用组件**：`PageHeader`、`FilterPanel`、`EmptyState`、`PaginationBar`、`SegmentedControl`。先落到学生、预警、积分这些已有重复结构的页面。
4. **统一统计与资料页组合**：`MetricStrip`、`ChartPanel`、`ProfileHeader`，复用现有真实数据，不先添加无数据的图表切换按钮。
5. **按业务需求补设置类控件**：`SettingRow`、`SwitchField`、`ChoiceCardGroup`。设置保存范围、接口权限、加载和失败反馈需一起设计。
6. **可选数据可视化**：只有逐日数据充分时增加状态带；无需为“像参考站”新增模型市场、钱包、计费、API 密钥、返佣等页面。

基础控件不应自己请求业务 API；页面或业务组件负责数据、权限和操作，基础控件只接收展示数据并发出事件。现有 `StudentPicker` 属于业务选择器，可以继续承担学生查询。

## 7. 后续验收清单

- 桌面和手机下标题、主操作、筛选、表格与分页不互相挤压；表格操作列可访问。
- 同类型按钮、字段、卡片和状态标签的尺寸、排版、状态表达跨页面一致；截图与项目之间的换肤色差不作为不通过项。
- 每个列表都核对加载、空数据、无搜索结果、错误、重试、末页删除后页码等状态。
- 每页条数改变、筛选改变时回到第一页；请求参数、总数与按钮禁用状态对应真实数据。
- 所有新增开关和偏好项具有真实生效范围和保存反馈，不制造装饰性“保存”按钮。
- 键盘可操作分段控件、选择卡、弹窗与表格动作，焦点可见；图表和状态色有文字说明。
- 不恢复已删除的顶栏导航、参考页入口或“视觉复原”标题。
